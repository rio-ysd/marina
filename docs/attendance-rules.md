# 勤怠に関するルール

## 定義
- （1日の）平均稼働時間
  - 週40時間の契約の場合は、平均稼働時間8時間となる

## シフトのルール
- 週に5日は入力すること
  - それ以下の場合は有給、もしくは休日申請をする
  - 振替出勤にする場合は平日の18時以降か休日のみ
    - 振替出勤の場合は同月内に整合性をとる
- 1日に平均稼働時間は最低でも入力すること
- 過去のシフトを修正は禁止
- 未来1ヶ月以内のシフトの編集
  - 減らすのは不可能
    - 店長の承認があればOK
  - 増やすのは可能

## 勤怠のルール
- 1分でも遅れた場合は、勤怠報告に反映する
- シフトの時間外に働くことは原則禁止
  - 施術がある場合は例外
  - 緊急性のある業務が発生した場合は店長に連絡して許可をもらうこと
- 6時間以上のときは1時間の休憩は必須

## 責任者がチェックするポイント
- シフトがシフトのルールに反していないかの確認
- 勤怠のルールに反していないかの確認
  - 残業はberyx_production.overtimesに理由も含まれて登録されてます
- Slackの#rino-security(C0BT3K6FTT3)のカメラの通知と比較して、遅刻していないか、最後にあった通知より遅くまで働いたことにしてないかの確認
- シフトが入っていないかの確認

## 報告フォーマット

問題がない日も省略せず、調査対象月と月単位の集計を含めて、次の順番で報告する。週単位の確認は、週5日未満または週の契約時間不足がある場合だけ記載する。
通常の調査対象は月単位とし、月途中の場合は基準日を付ける。特定事象の再調査など、日付範囲が必要な場合だけ開始日・終了日を指定する。

```
- スタッフ名(契約時間/週, 基準時間/日)
  - 調査対象月
    - YYYY年MM月
    - 月途中の場合: YYYY年MM月(MM/DD時点)
  - 期間サマリ
    - シフト日数: n日
    - 実働記録なし: n日
    - シフト不足: n日
    - シフト時間外: n日
    - 休憩不足: n日
    - 有給・休日申請: n日
    - 振替出勤: n日
    - 振替未解消: n件
  - 月別確認
    - YYYY年MM月
      - シフト日数: n日
      - 稼働時間: n時間 / 契約n時間
      - 有給・休日申請: n日
      - 振替出勤
        - 振替元: MM/DD
        - 振替先: MM/DD HH:MM-HH:MM
        - 同月内の整合性: あり / なし / 要確認
      - 問題点
        - 振替未解消
          - MM/DDの振替元または振替先が未確認
  - 日別
    - MM/DD
      - 実働 / シフト
        - HH:MM-HH:MM / HH:MM-HH:MM
      - 問題点
        - 実働記録なし
          - 欠勤・有給・休日申請を確認
        - シフト不足
          - n時間
        - 遅刻
          - n分
        - 早退
          - n分
        - シフト時間外
          - n時間
        - 休憩不足
          - 必要1時間 / 実績n分
        - 時間重複
          - n時間(HH:MM-HH:MM)
        - 防犯センサー
          - HH:MM-HH:MM
          - 開始n分遅い
          - 終了n分早い
      - 申請・承認
        - 残業申請: あり / なし / 要確認
```

### 報告時の注意

- 「実働記録なし」は欠勤と断定せず、有給・休日・振替出勤の申請を確認する。
- シフト時間外の勤務は、施術または緊急業務の理由、残業申請、店長の許可を確認する。
- 6時間以上の勤務は、休憩1時間との差分を報告する。
- 月のシフト日数・稼働時間・有給・休日申請・振替出勤を月単位で集計する。
- 通常の調査対象は月単位とする。月途中の場合は「YYYY年MM月(MM/DD時点)」とし、特定事象の再調査などで日付範囲を指定する場合は「YYYY-MM-DD〜YYYY-MM-DD」と記載する。
- 週5日未満や契約時間不足は週単位で確認するが、該当する週だけ報告する。有給・休日・振替出勤を考慮せずに不足と断定しない。
- 振替出勤は、振替元・振替先が同じ月にあり、平日18時以降または休日に行われているかを確認する。対応関係が確認できない場合は「振替未解消」または「要確認」と報告する。
- 過去シフトの変更、未来シフトの減少、同月内の振替の整合性は、変更履歴・申請・承認情報を確認できる場合だけ判定する。確認できない場合は「要確認」と報告する。
- 問題がない項目を無理に作らず、月別・日別の該当箇所に「なし」と記載する。週別確認は問題がある週だけ記載する。
